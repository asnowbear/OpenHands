Color theme · additive

Ember joins the settings picker

Canvas gains one dark palette, ember, labeled Ember. The existing registry already feeds Settings → Application → Color Theme, so registering the definition is what makes it selectable. OpenHands-Neutral stays the default.

1What changed

★ Ember is a firelit umber dark theme, not a recolor of Neutral, DeepSea, Neo, Light+, Solarized Light, or Paper. Copper (#E39A4A) fills primary actions. Peach (#FFC48A) is the link and focus ring. Body text stays ivory on umber at about 13.8:1 in the running mock app.

Each neutral step keeps the luminance of the matching OpenHands-Neutral grey, so inherited status inks (danger, success, warning, Markdown alerts) keep the contrast they already have. The hue is brown. Code, diffs, and the terminal get their own palettes instead of borrowing vscDarkPlus or the shared dark ANSI set.

3How a selection applies

ⓘ Theme names stay English proper nouns, the same way Paper, Light+, and OpenHands-Neutral do. The field label already uses SETTINGS$COLOR_THEME. No new translation key.

5Compatibility

⚠ Local and Cloud, OpenHands and ACP, and standalone and embedded Canvas share this picker and setColorTheme. The palette is presentation only. It does not change conversation payloads, prompts, or the Agent Server.

Embedded roots still wait until a palette is applied. A stored ember key is valid for the head bootstrap because the bootstrap script is generated from COLOR_THEMES. Switching away replaces the override stylesheet, so Ember tokens do not stick.

Contrast locked by the existing all-theme suite plus Ember-specific Prism and ANSI checks: body text 4.5:1, focus ring 3:1 on base, modal, raised, and hover surfaces.
